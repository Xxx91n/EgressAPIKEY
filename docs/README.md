# docs/ — Documentation Directory

## Structure

| Path | Purpose | Diataxis quadrant |
|---|---|---|
| `architecture/` | System architecture, design decisions, upstream integration | Explanation |
| `how-to/` | Operational guides (deployment, release, runbook, troubleshooting) | How-to |
| `reference/` | Glossary, API references | Reference |
| `research/` | Research findings, protocol analysis | Explanation |
| `agents/` | Agent instruction layer — not user docs; see `agents/README.md` | Reference |
| `RELEASE_NOTES.md` | Per-release notes, compatibility declarations | Reference |
| `RESIN_UPSTREAM_MANIFEST.yaml` | Pinned Resin upstream version manifest (read by `scripts/fetch_resin.sh`) | Reference |
| `I18N_CONTENT_MANIFEST.json` | i18n copy fingerprint manifest — generated by `node scripts/i18n-content-check.cjs --update`, never edited by hand | Reference |

## Conventions

- All migrations use `git mv` (preserves history, R100 = content unchanged).
- Constraint docs stay at `docs/` top level. Retired docs are deleted, not archived in-tree — history lives in git.
- Session-local working files are out of scope here: `.scratch/`, `.codex-tmp/`, `.opencode/`, `.zcode/`, `.omx/` are never committed. `.gitignore` is the authority for that list.
