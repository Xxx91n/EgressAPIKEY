## 18. P9 hardening - process routing, log rotation, test closed-loops, i18n seed sync

- **Process routing (issue 3 + 10)**: three new `#[tauri::command]` in `src-tauri/src/commands/mod.rs` now own the per-process -> lane routing-rule registry.
  - `process_route_add(app, process, target_lane)` - validates name (1..128 chars, no control per AGENTS <language uri>§7.5), lane range `0..MAX_LANES=50`, persistence via `tauri-plugin-store` key `processRoutes`. REJECTS via a pure helper `process_route_conflict_check(existing, new_process, new_lane)` BEFORE recording if the same target lane is already bound to a DIFFERENT process - the conflict surfaces as a typed `Err(String)` to the IPC caller.
  - `process_route_remove(app, process)` - deletes by name.
  - `process_route_list(app) -> Vec<ProcessRouteRule>` - reads persistent rules; the frontend rehydrates from this on mount.
  - The `ProcessRouteRule { process: String, target_lane: usize }` struct is `Serialize + Deserialize` so it round-trips through serde_json::Value (AGENTS §7.6 - server-trusted store, never exposed via a raw-String constructor in the webview).
  - Frontend: `src/views/ProcessRouteView.tsx` round-trips through the IPC wrappers `ipcProcessRouteAdd/Remove/List` in `src/lib/ipc.ts` (TS-boundary lane-range + name guards per AGENTS §7.6). On conflict the UI surfaces `t("processRoute.conflict")` as a red toast; on success `t("processRoute.backendSaved")`.
- **Log hardening (issue 11)**: `src-tauri/src/main.rs` configures tauri-plugin-tracing with `with_rotation(Rotation::Daily)` + `with_max_file_size(MaxFileSize::mb(10))` + `with_rotation_strategy(RotationStrategy::KeepSome(7))` so a runaway log stream cannot overflow the user's disk past 7 daily files or 10 MB each. A `std::panic::set_hook` installed at the top of `fn main()` captures panics into the same `tracing::error!` pipeline with a backtrace so a crashed sidecar thread surfaces a log line instead of silently unwinding; the original hook is chained.
- **Settings unified save (issue 6)**: `src/views/SettingsView.tsx` now exposes a single sticky bottom Save bar covering lanes/gatewayBind/mihomoApi. The previous per-card Save buttons are removed (comments keep their place). The unified Save sets a `busy` state and disables the button until the round-trip completes; it uses the existing `saveAll()` body unchanged.
- **Test closed-loops (issue 1)**:
  - `src/lib/subDrag.test.ts` - closed-loop coverage of the drag-reorder helper (begin / enter / finish / cancel + right-button ignore).
  - `src/lib/ipc.test.ts` - mocks `@tauri-apps/api/core::invoke` and asserts: (1) platform_add/remove/list forward the right command name with the right args; (2) account_add LANE_OUT_OF_RANGE guard fires BEFORE invoke; (3) subscription_add URL-shape guard fires BEFORE invoke; (4) process_route_add/Remove/List forward + the lane-range guard; (5) empty-name / control-char rejection at the TS boundary.

### 22. P13 - subscription/platform real backend loop + log observability

- **B6 + B4 root cause (items-wrapper bug)**: Resin wraps every list endpoint as `{"items":[...], "total", "limit", "offset"}`, NOT a bare array. The old `platform_names` / `platform_id_for_name` / `subscription_snapshot` / `subscription_id_for_name` helpers in `src-tauri/src/commands/mod.rs` used `v.as_array()` which is always `None` for the items shape - so `platform_list` returned `[]` (B6 list never populated) and `subscription_list` returned `[]` (B4 node count always 0). Fix: new shared helper `fn items_arr<'a>(v: &'a serde_json::Value) -> &'a [serde_json::Value]` accepts BOTH the items-wrapper and a bare-array back-compat path; all four helpers now call it. `per_platform_active_from_leases` was also rewritten to use `items_arr(platforms)` (the old `platforms.as_array()` had the same bug). 7 new unit tests pin both shapes.
- **B4 real backend loop (clash UA + flow->block convert + local POST)**: `crates/resin-core/src/resin_client.rs` ships two new free functions:
  - `pub async fn fetch_clash_subscription(url) -> Result<String>` builds a separate reqwest::Client (15s timeout, 5 redirects) and rotates 4 clash-family UAs. Many subscription providers (the user test host included) return 403 to a default UA but 200 + full Clash YAML to a clash client UA. Resin's own remote-fetch uses a default UA and was getting 403 - so its `node_count` stayed 0 forever. We bypass it: the shell fetches the YAML itself.
  - `pub fn clash_yaml_to_proxies_block(input) -> Result<String>` is a hand-written state machine (~140 lines, NO serde_yaml dep). It extracts the top-level `proxies:` segment, rewrites every flow-style `- { k: v, k: v }` list item into block-style, drops `proxy-groups`/`rules`/`dns`. Resin's Go YAML parser chokes on flow-style inline mappings and on unicode group names; this is the narrowest transform that fixes the user's 53-proxy test subscription. `fn split_flow_fields(s)` handles single-quote-escaped commas inside values.
  - `subscription_add` command rewritten: fetch YAML -> convert -> POST `{name, source_type:"local", content:<block>, url, update_interval:"30s"}` to Resin. 30s interval so Resin's scheduler parses the local content on the first tick (seconds, not the default 5m); Resin has no public force-refresh endpoint. Every step emits `tracing::info!`/`tracing::warn!` into the same log file (B5).
- **B5 log observability**: the existing `tauri-plugin-tracing` rotation (daily, 10MB, keep 7) already covers the file appender; the new `subscription_add` path adds `tracing::info!(subscription, url, "fetching clash yaml")`, `tracing::info!(bytes, "fetched yaml, converting")`, `tracing::info!(block_bytes, "posting local subscription")`, plus `tracing::warn!` on fetch/convert/POST failure. ### 23. P17-R2 - Topology canvas three-column key-to-egress redesign

- **Phase R2 complete**: the TopologyView is no longer a 2-column entry->lane mirror. It is now a three-column A/B/C key-to-egress routing canvas backed by live Resin platform + node data.
- **A (entry proxy port)**: single blue node on the left, the conceptual Resin forward-proxy entry point. Always-connected to every platform via animated edges.
- **B (platforms)**: one node per platform from `ipcPlatformListFull()` (GET /api/v1/platforms full objects). Each platform node shows name + a sub-line with regex_filters (upstream hosts), allocation_policy, routable_node_count. Custom `PlatformNode` component with left+right ReactFlow Handles.
- **C (IP channels / nodes)**: one node per NODE-REGION-GROUP from `ipcNodeList()` (GET /api/v1/nodes), grouped by region (lowercased from `region` field or 1-3 char tags). Each group node shows region + healthy/total count. Custom `NodeGroupNode` component with left Handle.
- **B->C edges = region_filters binding**: an edge is drawn from a platform to a node-group when the platform's `region_filters` array includes the group's region. This is the faithful mapping of the user's "drag line from platform to IP channel" intent to Resin's actual API (region-based node selection, NOT per-node).
- **Drag-to-connect = live hot PATCH**: `onConnect` detects a connection from `platform-<name>` to `nodegroup-<region>` and calls `ipcPlatformUpdate(name, undefined, undefined, [...current, region])` which PATCHes the platform's region_filters on the live Resin sidecar. The edge appears instantly (optimistic local state update) and Resin picks up the new binding for subsequent requests. Deleting an edge = PATCH region_filters to remove that region.
- **IPC gap fixed (R1 followup)**: `platform_update` Rust command + `ipcPlatformUpdate` TS wrapper now accept a `region_filters` parameter (was missing in R1). Region codes are lowercase ISO 3166-1 alpha-2 or !negation, max 16 chars, max 64 entries, no control/space chars. Validated at both TS and Rust boundaries (AGENTS §7.5).
- **Node schema reality**: Resin v1.2.0 GET /api/v1/nodes returns node_hash, display_tag, has_outbound, failure_count, region, tags. There is NO per-node egress_ip field. The canvas shows display_tag + health; the aggregate egress_ip_count lives only in the node-pool snapshot. This is documented in docs/architecture/REFACTOR_PLAN.md.
- **Bug #1 + #2 (carried from P15)**: topology flash on boot was fixed by the App.tsx bootstrap gate (holds a loader until persisted view is read, so the default "topology" view never flashes before the saved view swaps in). Blank canvas on refocus was fixed by the `visibilitychange` listener that re-syncs on refocus (the 5s poll can be throttled when the window is hidden). Both fixes are preserved in the R2 rewrite.
- **i18n**: 12 new topology keys added across all 18 locales (entryPort, platformsCol, nodesCol, dragHint, region, healthy, unhealthy, noNodes, noPlatforms, policy, routable, filters). `pnpm i18n:check` = 98 keys / 18 locales.

### 24. P19 - topology viewport memory + subscriptions drag/rename + key+endpoint research + drag-auto-backup + protocol weight research

- **Item 1: Topology viewport memory**: `src/views/TopologyView.tsx` now wraps the canvas in `ReactFlowProvider` and the inner `TopologyCanvas` uses the `useReactFlow()` hook. On mount we call `loadTopologyViewport()` (new helper in `src/lib/settings.ts` reading `settings.json#topologyViewport` via `tauri-plugin-store`) and `reactFlow.setViewport({x,y,zoom})` before the first data sync. - **Item 6 (drag root cause + rename)**: the original `finishDrag` correctly flipped `live[]`, but the 10s auto-poll `refresh()` immediately replaced the user hand-order with the Resin server sort, so the drag appeared broken despite the lib working. **Fix**: new `localOrder: string[]` state in `SubscriptionsView` plus `loadSubOrder()` / `saveSubOrder()` persistence; `applyOrder(lst, order)` sorts every fresh server batch by the saved local order with new subs appended at the tail. ### 66. T22 - headless white-screen fix (isTauri guard + SPA fallback + ErrorBoundary + items-unwrap) (ADR-0049)

**ADR-0049** (3-layer strategy: L1 isTauri guard + L2 SPA fallback + L3 ErrorBoundary): docs/adr/0049-headless-white-screen-spa-fallback-error-boundary.md. Plan: docs/GRILL_T22_HEADLESS_RENDERING_FIX.md (6 decisions + 5 phases + acceptance criteria).

- **Root cause (white screen)**: src/lib/ipc.ts ipcWatchPortHealth unconditionally constructed a Tauri Channel object and passed it to invoke().
