## 12. Resin sidecar runtime (G1, P4 path A)

- **Live**: `src-tauri/src/sidecar.rs` `boot_resin()` is called from `main.rs` `.setup()`. It allocates a free loopback port, generates an admin token (32 hex chars, stdrand-based — see `gen_token()` unit tests) and sets proxy_token to empty (ADR-0027: empty token enables no-auth on ports where require_proxy_auth_info=0), resolves the per-user `state/cache/log` dirs from `tauri::Manager::path()` (`app_data_dir()` + `app_log_dir()`), spawns the Go `resin-x86_64-pc-<abi>.exe` sidecar via `tauri_plugin_shell::ShellExt::sidecar("resin")`, sets `RESIN_AUTH_VERSION=V1`, `RESIN_ADMIN_TOKEN`, `RESIN_PROXY_TOKEN`, `RESIN_LISTEN_ADDRESS=127.0.0.1`, `RESIN_PORT`, and **`RESIN_STATE_DIR` / `RESIN_CACHE_DIR` / `RESIN_LOG_DIR` (the Go binary defaults to `/var/lib/resin`, `/var/cache/resin`, `/var/log/resin` which do not exist on Windows and crash with `fatal: persistence bootstrap: repair consistency: attach state_db: unable to open database file ... (14)`)**, and polls the sidecar `/healthz` (NOT `/health` — that returns 403; Resin's unauthenticated health endpoint is `GET /healthz` per `DESIGN.md` Admin API Token section) until the control plane is reachable (15s deadline). Holds the child `CommandChild` + tokens in `State<SidecarHandle>`. The admin token NEVER crosses into the webview; only Rust-side ResinClient (G2) will read it.
- **Bundle wiring**: `src-tauri/tauri.conf.json` `bundle.externalBin = ["binaries/resin"]`. Tauri appends the host target triple (`-x86_64-pc-windows-msvc` or `-x86_64-pc-windows-gnu` depending on installed toolchain; use `rustc -vV` to confirm) and platform extension. Capabilities `src-tauri/capabilities/default.json` includes `shell:allow-spawn` + `shell:allow-kill` + `shell:allow-stdin-write`.
- **Sidecar binary sourcing**: `src-tauri/binaries/resin-<triple>[.exe]` is **gitignored** (see `.gitignore` block). The ~38MB Go binary is fetched per-platform by `scripts/fetch_resin.{ps1,sh}` from the upstream `github.com/Resinat/Resin/releases/download/v1.2.0/` asset (version per `docs/RESIN_UPSTREAM_MANIFEST.yaml`, ADR-0017) matching the host triple. CI MUST run the fetch script before `tauri build`. The host developer can run `scripts/fetch_resin.ps1` (Windows) or `scripts/fetch_resin.sh` (macOS/Linux) once after clone.
- **Smoke verified**: release exe (`cargo build --release -p egressapikey-app --features custom-protocol`) boots, `MainWindowTitle = "EgressAPIKEY"`, WorkingSet ~36MB, `resin.exe` child process spawned, `/healthz` returns 200 within 15s (typically 0ms on this host), sidecar SQLite `state.db` + `cache.db` + `country.mmdb` (GeoIP) created under `%APPDATA%/com.egressapikey.desktop/resin-*`. See G1 commit message for the pid/title/logs evidence.
- **[Archived — superseded by ADR-0050]**: the mihomo-controller bullet that lived here described `crates/resin-core/src/mihomo.rs`, a module deleted by ADR-0050 (original text in git history). The standing rule survives in AGENTS.md §7.6: a reintroduced mihomo REST controller must re-assert the loopback-only guard and must never be constructed from a frontend-controlled string.

## 13. Ghost safety net (G3, P4 path A)

- **Live**: `src-tauri/src/sidecar.rs` additionally owns `spawn_health_poll(app_handle)`. Called once from `main.rs .setup()` after `app.manage(SidecarHandle)`. Polls `http://127.0.0.1:<api_port>/healthz` (2s reqwest timeout) every 3s. After **3 consecutive failures** the tray flips red, the OS system HTTP/HTTPS proxy is cleared (Windows: `reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings /v ProxyEnable /t REG_DWORD /d 0 /f`; macOS: `networksetup -setwebproxystate <svc> off` per service; Linux GNOME: `gsettings set org.gnome.system.proxy mode none`), and a `sidecar-status` event with payload `"unhealthy"` is emitted to the webview. On the next successful /healthz the tray flips green and a `"healthy"` event is emitted. A-012 (round 8, D-005 ii): the unhealthy branch no longer just announces a restart - it performs one (two-phase kill of the child -> respawn on the SAME control-plane port with the same admin token via `respawn_resin_await_healthz` -> await /healthz -> swap the new child into `State<SidecarHandle>`), up to MAX_CRASH_RESTARTS=3 attempts with 1s/2s/4s backoff; the next unhealthy transition after the budget is exhausted marks the sidecar Terminated. The red-tray / OS-proxy-clear / event contract is unchanged. No `tauri-plugin-notification` dependency (Ponytail: React shell renders an event-driven banner; G4 wires the listener).
- **Async health probe**: async `reqwest::Client` inside `tauri::async_runtime::spawn`; each poll bounded by a 2s reqwest timeout so a hung sidecar cannot stall the net.
- **Smoke verified**: release exe boots green; manual `Stop-Process -Id <resin.exe>` -> ~9s later stdout reads "ghost: sidecar /healthz fail #1/#2/#3" + "ghost: sidecar unhealthy after 3 failures; marking tray red + clearing OS proxy". See G3 commit message for the full log.
- **Security**: the probe itself stays observation-only (no shell traffic is ever routed or credentials touched); the RESTART it triggers is bounded and explicit - at most MAX_CRASH_RESTARTS=3 attempts with 1s/2s/4s backoff, then the sidecar is marked Terminated and the app must be restarted by the user (A-012). The restart re-runs the shared spawn helper, not a second `boot_resin`, and never re-allocates the control-plane port.
- **Contract event name**: `sidecar-status`. Payload: literal string `"healthy"` or `"unhealthy"` (no object). Frontend subscribes via `@tauri-apps/api/event`.

## 14. ResinClient (G2 phase 1, P4 path A)

- **Live**: `crates/resin-core/src/resin_client.rs` ships a loopback-only async REST client for the Resin sidecar admin API. Constructed from `SidecarHandle::api_base()` + `admin_token` (the only caller will be the IPC commands layer; the webview NEVER receives the admin token). Loopback host guard rejects non-loopback bases with an error in all builds (defense-in-depth; it originally mirrored the mihomo-controller guard style, since deleted by ADR-0050).
- **Endpoints implemented**: `create_platform(body)`, `create_platform_from_name(name)` (with V1 name validation), `list_platforms()`, `get_platform(id)`, `delete_platform(id)`, `active_leases()` (GET /api/v1/metrics/realtime/leases — replaces the dead resin-core `LeaseTable` for the Topology view), `node_pool_snapshot()` (GET /api/v1/metrics/snapshots/node-pool).
- **Bearer auth**: every admin request attaches `Authorization: Bearer <admin_token>` automatically. `.send(...)` returns JSON Value on success; on non-2xx it errors with the upstream status + a 256-byte body excerpt so the frontend gets a useful message instead of an opaque swallow.
- **Tests**: `resin_client.rs` unit tests — plain loopback/URL guards plus offline-integration via mockito 1.7 (dev-dependency) covering the platform / subscription / endpoint / lease / request-log verbs. Counts as of 2026-09-02: 30 tests in the module; `cargo test -p resin-core --lib` = 198 passed, 0 failed. (The earlier "6 module tests / 52 crate" figures predate the ADR-0050 surface shrink and the ticket-11 request-log additions.)
- **Ponytail**: not an SDK — only the verbs the IPC layer currently needs. Any request body is `serde_json::Value` so the React form's payload passes through verbatim. No per-endpoint struct modeling until we actually need it.
- **G2 phase 2: LANDED — see §15.** The retarget plan written here (forward the then-11 IPC commands to `ResinClient`, echo/no-op the gateway verbs, keep `.get_config_dir/.get_log_dir/.tray_refresh_labels` unchanged) was executed in the §15 commit; the original plan text is preserved in git history.

## 11. Runtime wiring state (post-#6 phase 1 sync)

- **Settings ingestion (archived T3-A history)**: pre-T3-A, `src-tauri/src/main.rs` `.setup()` read two legacy network preference keys (purged from settings.json by arch/02) + `laneCount` from `tauri-plugin-store` into the shell config struct and dropped it with `let _ = cfg;` — pure dead code with zero runtime effect (ADR-0012 thin-shell delegates the actual listen port to the Resin sidecar via `pick_free_loopback_port`). T3-A removed the dead block + the now-unused `StoreExt` import; the live settings path is `app.path()` + the `port_mappings` SQLite store + the whitebox config store. (The tail that claimed a lane-count env fallback still fed the shared-gateway builder was itself stale — ADR-0024 had already deleted that fallback, the builder, and the gateway.)
- **TopologyView IPC**: `src/views/TopologyView.tsx` consumes the single authoritative snapshot (`ipcAuthoritativeSnapshot`, ticket 07 / ADR-0051) on mount + a 5s poll (usePoll) and rebuilds platforms/ports from the pre-merged snapshot; the former view-layer cross-store merge is deleted. Outside Tauri (vitest) the IPC throws silently and the view keeps its local Zustand state — tests do not depend on the IPC.
- **Proxy runtime ownership (settled by ADR-0012/0015 + ADR-0050)**: the data path runs in the Resin Go sidecar; the shell-side kernel modules (gateway/lane/lease/tdewma/mihomo) were deleted from resin-core by ADR-0050. There is no Rust-side proxy runtime in the shell — no axum forward, no lane machine, no mihomo lifecycle; any future server-parity work restarts from the headless bin (ADR-0043/0050), not a shell-side kernel. Anything claiming the proxy runs end-to-end in Rust is false.
- **SSRF guard note (archived — superseded by ADR-0050)**: the `debug_assert!` release-panic analysis that lived here described the shell-side mihomo controller (`crates/resin-core/src/mihomo.rs`), deleted by ADR-0050 (original text in git history). The surviving equivalent: `ResinClient::new` rejects non-loopback bases with a typed error in all builds; if a mihomo controller is ever reintroduced, its loopback-only guard MUST be re-asserted first (AGENTS.md §7.6).

## 15. IPC retarget to Resin (G2 phase 2, landed)

- **Retarget**: the then-eleven `#[tauri::command]` (all resident in `src-tauri/src/commands/mod.rs` at retarget time) no longer locked the self-implemented `SharedGateway` / `SharedRegistry`. Platform commands forward to the live Resin Go sidecar via `resin_core::ResinClient` built from `State<SidecarHandle>` (G1 manages `SidecarHandle` into Tauri state; the admin token stays Rust-side, never crosses into the webview — AGENTS §7.6). [Structure as-built — tickets 08/23]: the commands monolith has since been split into six domain modules (`platform.rs` / `strategy.rs` / `ports.rs` / `backup.rs` / `settings.rs` / `diagnostics.rs`, plus `common.rs` / `tests.rs`); `src-tauri/src/commands/mod.rs` is now a thin re-export facade with zero `#[tauri::command]`, and the live IPC surface is 67 commands (AGENTS §7.6 manifest) after ticket 23 removed four dead lanes from the earlier 71.
- **Forward commands**: `platform_add` -> `POST /api/v1/platforms` (via `create_platform_from_name`); `platform_remove` -> `list_platforms()` then name -> id match then `DELETE /api/v1/platforms/{id}`; `platform_list` -> `GET /api/v1/platforms` then project `name`. [Removed — ticket 23 / commit arch/23]: `platform_snapshot` (then an echo validating the name and returning an empty `Vec<Account>`, on the reasoning that Resin accounts are subscription nodes and the manual per-platform lane/exit_ip bind surface does not exist in Resin) was deleted with zero consumers; TopologyView reads leases through `lease_map` (`ipcLeaseMap`). Original text in git history.
- **Echo / no-op commands (Resin owns the semantics)**: `account_add` / `account_bind_ip` still validate every IPC input (length caps, control chars, and for `account_add` the lane range) so a hostile webview cannot reach Resin, but their bodies return `Ok` status echoes — Resin's forward proxy + TD-EWMA run natively. This keeps the frontend IPC contract stable; the React Platform screens kept the shell's own account-handling UX (G4 landed without forking Resin's webui — §16). [Removed — T4-1 / ADR-0024, commit 4649dd2]: the five `gateway_reserve` / `gateway_release` / `gateway_evict_lane` / `gateway_record_latency` / `gateway_select_account` echo lanes this bullet once covered were deleted as dead stubs; original text in git history.
- **[Removed — ticket 23 / commit arch/23]**: the `gateway_snapshot` bullet that lived here described the deleted lease-count read from `GET /api/v1/metrics/realtime/leases` (with `lane_count` reporting `resin_core::MAX_LANES` to keep the 50-lane canvas shape, and `latencies` empty because Resin owns per-authority EMA internally); the whole lane — command, TS wrapper, tests, and the `LaneSnapshot` machinery — was deleted with zero consumers, and TopologyView now gets lease counts through `lease_map` (`ipcLeaseMap`). Original text in git history.
- **Unit tests**: `platform_names_projects_name_field` / `platform_id_for_name_matches` are retained, now in `src-tauri/src/commands/tests.rs` (the ticket-08 domain split moved them out of `commands/mod.rs`), alongside the retained `validate_ip` / `validate_short_name` guards. [Removed — ticket 23 / commit arch/23]: `sum_active_leases_parses_resin_shape` (went with the `gateway_snapshot` lane and the `LaneSnapshot` machinery). [Removed — T4-1 / ADR-0024]: `validate_authority`.
- **Host note**: `cargo test -p egressapikey-app --features custom-protocol --lib` test binary exits with `STATUS_ENTRYPOINT_NOTFOUND (0xc0000139)` on THIS dev host (the recorded Tauri native-plugin DLL linker issue, environmental NOT code). `cargo build -p egressapikey-app --features custom-protocol` is green; `cargo test -p resin-core --lib` = 52 passed; `ResinClient` mockito tests cover the offline round trip. ## 16. Resin → shell signal channel (G4: IPC retarget + sidecar-status event subscription, current commit)

> Canonical wording: the Resin → shell signal = `app.listen("sidecar-status")` event subscription (no HTTP webhook endpoint — the Resin upstream Admin API is a pure pull model).

- **Ponytail decision**: we did NOT physically copy Resin's `webui/` React app into a new `src/resin-views/`. The existing 5-tab desktop shell (Topology / Platforms / Subscriptions / ProcessRoute / Settings) already owns the desktop UX surface (Tauri webview, tray, theme, i18n); forking Resin's own providers/api/store/vite config would have re-engineered a working frontend for net-zero visual change. The real fork contract is making the shell SEE the live Resin data, which is the ResinClient + IPC retarget (G2 phase 2 + this commit).
- **ResinClient now (3 endpoints added)**: `create_subscription(body)`, `list_subscriptions()`, `delete_subscription(id)` under `/api/v1/subscriptions`. `node_pool_snapshot()` already existed. The loopback + bearer-auth + non-2xx-error-excerpt guards are shared with the platform methods.
- **4 new IPC commands**: `subscription_add(name, url)` (with a URL-shape `(http|https)://` guard + length cap BEFORE reaching Resin), `subscription_remove(name)`, `subscription_list() -> (name, node_count)[]`, `node_pool_snapshot() -> serde_json::Value`. Same name-based contract as platform_remove: list -> match name -> id; frontend never has to know Resin UUIDs.
- **SubscriptionsView rewritten**: the import form now has a name + url field, and add/list/remove round-trip through the live Resin sidecar. The local appStore reducer stays the optimistic fallback (so the screen is never blank if the sidecar never came up or in the Vite dev preview without IPC).
- **TopologyView sidecar-status banner**: TopologyView now imports `listen` from `@tauri-apps/api/event` and subscribes to the G3 contract event `sidecar-status`. On payload `\"unhealthy\"` it raises a red `AlertTriangle` banner above the canvas (`topology.sidecarUnhealthy` i18n key, added to all 18 locales). On `\"healthy\"` the banner is hidden. Outside Tauri, `listen()` rejects gracefully and the canvas renders without a banner.
- **i18n**: 2 new keys added across all 18 base locales: `subscription.name`, `topology.sidecarUnhealthy`. `pnpm i18n:check` = 62 keys all match.
- **Tests**: `crates/resin-core/src/resin_client.rs` has 2 new mockito tests (`mockito_create_subscription_happy_path`, `mockito_delete_subscription_204_no_content_round_trip`); `cargo test -p resin-core --lib` = 54 passed. `pnpm test` (vitest) = 6 passed (`appStore.test.ts`). `pnpm build` (tsc + vite) green with locale-split chunks. `e2e/tab_switch.spec.ts` + `e2e/platform_round_trip.spec.ts` are the frontend contract tests (Playwright browsers are a CI-side resource; host did not have `pnpm exec playwright install` so local e2e skipped voluntarily).

## 17. CI/CD release pipeline (G5, current commit)

- **What shipped in this commit**: the existing `.github/workflows/ci.yml` already implements the release-pipeline spec the user asked for (5 jobs: verify, e2e, backend headless matrix, gui installer matrix, gui-portable matrix). The G5 delta is wiring each GUI job (installer + portable) to FETCH the Resin Go sidecar binary into `src-tauri/binaries/resin-<triple>` BEFORE running `tauri build`. Without that binary, `tauri build` produces a GUI bundle that boots into `boot_resin` then fails inside `ShellExt::sidecar("resin")` with `externalBin misconfigured`.
- **fetch step**: added `- name: fetch Resin Go sidecar binary` in both the `gui` installer job and the `gui-portable` job, right after `pnpm install --frozen-lockfile`. It is `shell: bash` running `bash scripts/fetch_resin.sh`; `fetch_resin.sh` resolves the host triple via `rustc -vV host:` and the CI matrix builds natively (host triple == target triple), so one call covers each matrix OS.
- **fetch_resin.sh now portable**: previously relied on `unzip -q` for the windows-amd64 .zip release asset, which the Windows runner does not ship. Now falls back to `powershell -NoProfile -Command "Expand-Archive ... -Force"` when `unzip` is absent. Linux / macOS paths unchanged (tarball extraction).
- **verify-build.sh sidecar guard**: the tail of `scripts/verify-build.sh` now scans `src-tauri/binaries/resin-*` and emits a WARN if no file over 1MB is present. It does NOT fail (the verify job is backend-only and intentionally does not need the GUI sidecar); it surfaces a hint in the CI log if a GUI-artifact job ever forgets the fetch step.
- **artifact groups (per the standing user requirement)**: `<os>-backend` (tar.gz), `<os>-gui-installers` (msi / setup.exe / deb / AppImage / dmg) and `<os>-gui-portable` (single `EgressAPIKEY.exe` / `EgressAPIKEY`). Each GUI matrix OS ships BOTH installer bundles AND the drop-and-run portable binary. The portable binary is named exactly `EgressAPIKEY.exe` (Windows), `EgressAPIKEY` (Linux/macOS), matching the user requirement "every GUI variant must ship an installer variant and a convenient portable variant".
- **iOS GUI**: explicitly NOT built - a Tauri desktop shell does not run on iPadOS; the Apple-silicon desktop sibling is the macOS `.dmg`. Documented in README and in this file.
