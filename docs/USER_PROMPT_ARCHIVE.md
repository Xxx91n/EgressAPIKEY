### 1. 订阅页面拖动行排序 bug

拖动行以重新排序的功能依旧始终不可用，拖动时会直接变成禁止的符号。建议参考 D:\Aworker\env-manager 这个同架构内的配置文件页面的排序功能如何实现；如果无法兼容适配，继续进入 debug 模式，根据目前架构 exa 和 pwm 联网根据代码实际内容更改。

### 需要大幅度重构平台功能

**1.** 识别每一个来自上游 ai 网关的 api key 组合之后，可以将其独立放置，也可以把其中几个放在一起组成一个"平台"，关键在于：要最好能识别此 api key 组合的唯一特征，保证算法能够将其识别为唯一性，而且不会受其他内容影响，唯一性来自于上游 v1 端点地址 + API key，导致不会有识别其他的 API key 组合之后直接把之前的 API key 组合覆盖/抢走。

**2.** 识别每一个来自上游 ai 网关的 api key 组合之后，系统要默认在组合页面中生成一个新的 api key 的唯一标识符，所以就需要重构平台页面，将其变为左右两个页面，中间可以调整左右的宽度：
- 左边放新识别到的 api key
- 右边放新建的平台/允许的 api key
- 将左边的 api key 可以直接拖进右边区域，表示开始启动端口出口 IP（如果没有用户手动放到右边，默认禁止端口出口，怕误操作导致 ip 污染 api key）
- 拖到右边区域的空白处，单独其为一个独立的 api key 组合
- 拖到右边区域的已有组合上内，把他放进组合
- 独立的 api key 组合不能被放进去其他 api key；要与新建的可放组合有外观审美区分
- 独立的 api key 组合还能再次拖动放进其他手动新建可放的组合中

**3.** 平台删除/排序移动的功能也需要同步到位。目前移动功能在订阅界面，虽然有显示"拖动行以重新排序"但并不能拖动，先把订阅界面的问题解决再搬过来。

### 需要大幅度新增的功能

**1. 每个ip/ip通道**：
- 都需要从订阅链接/本地文件中获取（需要白盒配置文件可控制，参考 clash-verge-rev）
- 对齐 Resin 支持的配置文件
- 需要新建 ip 通道的 GUI 界面，默认 ip 通道会根据策略自动生成几个
- 以后可以自己配各种 ip 通道部署的策略：随时测活放入可使用的 ip / 根据出口 ip 质量权重放入 / 自定义放入等等非常多内置策略
- ip 通道还可以设置 ip 出口策略：完全随机出口 / 按照顺序 / 按照延时高低 / 按照带宽高低 / 按照出口 ip 质量权重（外加节点的协议也需要加入权重，使用 pwm 深度研究模式研究节点协议对 AI api key 的 SSE 或 WebSocket 的影响）

**2.** 所有更改都必须对接配置层、数据库层，不要只在 GUI 上面像个玩具一样做秀，要对接后端真正功能闭环。
